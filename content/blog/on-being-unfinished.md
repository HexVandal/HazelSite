There are fourteen unfinished projects in my folder. Each one is roughly 80%
done and each one will probably stay that way, and I've stopped pretending
that's a character flaw.

## The 80% rule

The last 20% of any project is not the same work as the first 80%. The first
80% is discovery: you're learning the tool, the shape of the problem, what you
actually want. That part is fun and fast and mostly downhill.

The last 20% is maintenance disguised as progress. Tests, edge cases, the
settings page nobody asked for, the empty states, the error handling. It's
real work — the most valuable work, honestly — but it's not the work that
teaches you anything new.

So some projects are 80% done forever, and they were still worth building.

## What the drawer is actually for

The unfinished folder is not a graveyard. It's a library of solved problems.
Half the code in this site started as a dead side project at 80%. The blog
layout? From an abandoned portfolio. The colour palette? Stolen from a design
I gave up on in March.

Nothing is wasted. It's just early.

> Finish what pays you or what people use. The rest is practice, and practice
> doesn't need a release date.

## The one exception

There is one thing worth finishing: anything somebody else is waiting on. A
promise is the only deadline that isn't arbitrary. Everything else is a
self-imposed guilt schedule, and guilt is the worst project manager I've ever
worked with.
